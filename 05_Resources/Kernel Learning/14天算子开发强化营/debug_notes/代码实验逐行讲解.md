# 代码实验逐行讲解

这份文件解释 `code_labs` 里的核心代码。你可以边看代码边对照这里。

## 1. CUDA vector_add.cu

核心 kernel：

```cpp
__global__ void vector_add_kernel(const float* a, const float* b, float* c,
                                  int n) {
  int idx = blockIdx.x * blockDim.x + threadIdx.x;
  if (idx < n) {
    c[idx] = a[idx] + b[idx];
  }
}
```

逐行解释：

```cpp
__global__
```

表示这个函数是 device kernel，由 host 调用，在 GPU 上执行。

```cpp
int idx = blockIdx.x * blockDim.x + threadIdx.x;
```

把 block 编号和 block 内线程编号映射成全局元素下标。

```cpp
if (idx < n)
```

最后一个 block 可能多开线程，必须防止越界。

```cpp
c[idx] = a[idx] + b[idx];
```

每个线程处理一个元素。这个算子计算很少、读写很多，所以通常 memory-bound。

## 2. CUDA transpose.cu

naive transpose 核心：

```cpp
out[x * height + (y + j)] = in[(y + j) * width + x];
```

`in` 是 row-major：

```text
in[row, col] = in[row * width + col]
```

转置后：

```text
out[col, row] = out[col * height + row]
```

问题：

```text
相邻线程读 in 时通常连续；
但写 out 时可能跨很大 stride。
```

tiled transpose 核心：

```cpp
__shared__ float tile[TILE_DIM][TILE_DIM + 1];
```

shared memory tile 用于中转。`+1` 用于缓解 bank conflict。

```cpp
tile[threadIdx.y + j][threadIdx.x] = in[(y + j) * width + x];
```

连续读 global memory 到 shared memory。

```cpp
__syncthreads();
```

保证 tile 全部写好。

```cpp
out[(y + j) * height + x] = tile[threadIdx.x][threadIdx.y + j];
```

从 shared memory 转置读取，再尽量连续写 global memory。

## 3. CUDA reduction.cu

核心局部累加：

```cpp
float local = 0.0f;
for (int col = tid; col < cols; col += BLOCK_SIZE) {
  local += x[row * cols + col];
}
```

每个线程处理一行中的多个列，得到局部和。

写入 shared memory：

```cpp
smem[tid] = local;
__syncthreads();
```

所有线程把局部结果放进 shared memory。

树形归约：

```cpp
for (int stride = BLOCK_SIZE / 2; stride > 0; stride >>= 1) {
  if (tid < stride) {
    smem[tid] += smem[tid + stride];
  }
  __syncthreads();
}
```

每轮把后半部分加到前半部分，直到 `smem[0]` 是整行 sum。

写出：

```cpp
if (tid == 0) {
  y[row] = smem[0];
}
```

一个 block 只需要一个线程写最终结果。

## 4. Triton vector_add.py

核心：

```python
pid = tl.program_id(axis=0)
block_start = pid * BLOCK_SIZE
offsets = block_start + tl.arange(0, BLOCK_SIZE)
mask = offsets < n_elements
```

含义：

- `pid` 是当前 program 编号。
- `block_start` 是当前 block 的起点。
- `offsets` 是这一块所有元素的下标。
- `mask` 保护最后一块越界位置。

```python
x = tl.load(x_ptr + offsets, mask=mask)
y = tl.load(y_ptr + offsets, mask=mask)
out = x + y
tl.store(out_ptr + offsets, out, mask=mask)
```

一次处理一个 block 的向量。

## 5. Triton fused_softmax.py

核心：

```python
x = tl.load(x_ptr + row * n_cols + offsets, mask=mask, other=-float("inf"))
```

读取一行。越界位置填负无穷，不影响 max。

```python
x = x - tl.max(x, axis=0)
```

数值稳定，防止 exp 溢出。

```python
numerator = tl.exp(x)
denominator = tl.sum(numerator, axis=0)
y = numerator / denominator
```

完成 softmax。

为什么叫 fused：

```text
max、exp、sum、divide 都在一个 kernel 内完成，中间结果不写回 HBM。
```

## 6. Triton rmsnorm.py

核心：

```python
x = tl.load(...).to(tl.float32)
w = tl.load(...).to(tl.float32)
```

输入转 FP32 参与统计计算。

```python
mean_square = tl.sum(x * x, axis=0) / n_cols
inv_rms = tl.rsqrt(mean_square + eps)
```

RMSNorm 的核心统计量。

```python
y = x * inv_rms * w
```

归一化并乘 weight。

## 7. 读代码时的固定问题

每看一个 kernel，都问：

1. 一个 thread/program 负责什么数据？
2. 输入输出 shape 是什么？
3. 有没有边界 mask？
4. 读写是否连续？
5. 有没有中间结果写回 global memory？
6. accumulation dtype 是什么？
7. benchmark 是否正确同步？

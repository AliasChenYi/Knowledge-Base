# 算子开发排错手册

这份手册按“现象 -> 可能原因 -> 检查方法 -> 修复方向”组织。你写 CUDA/Triton/PyTorch custom op 时，遇到问题先来这里查。

## 1. CUDA 程序能编译，但运行输出全错

可能原因：

1. host 到 device 没拷贝输入。
2. kernel 没有实际覆盖所有元素。
3. 全局下标计算错。
4. grid size 没向上取整。
5. 输出 device 到 host 没拷贝回来。
6. kernel 发生了异步错误，但你没检查。

检查方法：

```cpp
cudaError_t err = cudaGetLastError();
printf("kernel error: %s\n", cudaGetErrorString(err));
cudaDeviceSynchronize();
```

修复方向：

- 检查 `idx = blockIdx.x * blockDim.x + threadIdx.x`。
- 检查 `grid = (n + block - 1) / block`。
- 检查 `if (idx < n)`。
- 每次 kernel 后先临时加同步定位。

## 2. 最后几个元素错

典型原因：

```text
边界处理错。
```

常见错误：

```cpp
int grid = n / block;  // wrong when n is not divisible by block
```

修复：

```cpp
int grid = (n + block - 1) / block;
```

并在 kernel 内：

```cpp
if (idx < n) {
  ...
}
```

## 3. GPU 计时几乎为 0

典型原因：

```text
kernel launch 是异步的，你只测到了提交开销。
```

错误写法：

```cpp
auto t0 = now();
kernel<<<grid, block>>>(...);
auto t1 = now();
```

修复：

- 用 CUDA event。
- 或至少在计时结束前 `cudaDeviceSynchronize()`。

## 4. 第一次运行特别慢

可能原因：

- CUDA context 初始化。
- JIT 编译。
- cache 未热。
- Triton 首次编译。

修复：

```text
正式计时前 warmup 10-100 次。
```

Triton 首次运行包含编译开销，benchmark 时要避开。

## 5. 结果偶发错误

可能原因：

- 少了同步。
- shared memory 数据竞争。
- 越界写导致未定义行为。
- 使用未初始化内存。

检查：

- 在 shared memory 写后、读前检查是否需要 `__syncthreads()`。
- 缩小 shape。
- 用固定输入。
- 每次运行后比对第一个 mismatch。

## 6. Reduction 对负数输入错

典型错误：

```cpp
float local = 0.0f;
local = fmaxf(local, x[i]);
```

如果输入全是负数，结果会错误变成 0。

修复：

```cpp
float local = -INFINITY;
```

## 7. Softmax 出现 NaN 或 Inf

可能原因：

1. 没有减最大值。
2. 输入本身有 NaN。
3. mask 位置填充值错。
4. denominator 为 0。

正确结构：

```text
m = max(x)
z = x - m
e = exp(z)
s = sum(e)
y = e / s
```

Triton 越界位置常填：

```python
other=-float("inf")
```

这样不会影响 max。

## 8. LayerNorm/RMSNorm 误差大

可能原因：

1. 半精度直接累加。
2. eps 加错位置。
3. mean/variance 定义和 reference 不一致。
4. 输出 cast 顺序不一致。

建议：

```text
FP16/BF16 输入，统计量用 FP32。
```

RMSNorm 参考：

```python
variance = x.float().pow(2).mean(dim=-1, keepdim=True)
y = x.float() * torch.rsqrt(variance + eps)
y = (y * weight).to(x.dtype)
```

## 9. Triton 报 mask 或越界相关错误

检查：

```python
offsets = block_start + tl.arange(0, BLOCK_SIZE)
mask = offsets < n_elements
tl.load(ptr + offsets, mask=mask)
tl.store(ptr + offsets, value, mask=mask)
```

常见错误：

- load 有 mask，store 忘了 mask。
- 二维矩阵 offset 算错。
- `BLOCK_SIZE` 小于实际行长度。

## 10. Triton 编译很慢

可能原因：

- 首次 JIT 编译。
- meta 参数组合太多。
- BLOCK_SIZE 太大。
- autotune 配置太多。

处理：

- 首次编译和 benchmark 分开。
- 减少搜索空间。
- 先固定少量参数跑通。

## 11. PyTorch custom op 找不到

可能原因：

1. 扩展没编译成功。
2. 动态库没 import。
3. namespace 写错。
4. schema 名字和 Python 调用不一致。

排查：

```python
print(torch.ops.my_ops)
```

确认：

```text
TORCH_LIBRARY(my_ops, m)
torch.ops.my_ops.rms_norm
```

namespace 要一致。

## 12. Benchmark 比 baseline 慢很多

先不要慌。可能原因很多：

- baseline 是 cuBLAS/cuDNN/PyTorch 高度优化实现。
- 你的 shape 太小，launch overhead 占主导。
- 没有 fusion 收益。
- 内存访问不连续。
- block/tile 参数不合适。
- 没用 Tensor Core。
- 测量方法不对。

你要做：

1. 先确认 correctness。
2. 确认计时方式正确。
3. 换多个 shape。
4. 用 profiler 找瓶颈。
5. 写出“慢在哪里”的证据。

## 13. 写性能报告时不要这样写

不要写：

```text
我的 kernel 比 PyTorch 快。
```

要写：

```text
在 A100、CUDA 12.x、FP16、shape=[4096,4096] 下，和 torch.softmax eager baseline 相比，我的 Triton fused softmax median latency 从 X ms 降到 Y ms。该收益主要来自减少中间 tensor 写回和 kernel launch 次数。对 shape=[32,128] 没有收益，可能是 launch overhead 占主导。
```

成熟工程表达的关键是：

- 硬件。
- 软件版本。
- shape。
- dtype。
- baseline。
- 指标。
- 解释。
- 限制。

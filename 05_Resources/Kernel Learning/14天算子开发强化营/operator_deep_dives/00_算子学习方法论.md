# 00：算子学习方法论

## 1. 学算子不要只背 API

算子开发最容易走偏的地方，是把学习变成 API 收集：

```text
今天看 CUDA API，明天看 Triton API，后天看 CUTLASS 模板。
```

这些都重要，但还不是核心。真正的主线是：

```text
数学语义 -> 张量布局 -> 并行映射 -> 内存访问 -> 数值精度 -> 测试 benchmark -> 框架接入
```

你每学一个算子，都应该按这条链路拆。

## 2. 一个算子的七层结构

### 第 1 层：数学语义

先问：

```text
它到底算什么？
```

例如 softmax：

```text
y_i = exp(x_i) / sum_j exp(x_j)
```

但真实语义还包括：

- 沿哪个维度做？
- 是否有 mask？
- 是否做 causal？
- dtype 是什么？
- NaN/Inf 怎么处理？

### 第 2 层：输入输出与 shape

写清：

```text
input: [M, N]
output: [M, N]
axis: last dimension
```

不要只写“支持 tensor”。shape 是性能的第一变量。

### 第 3 层：layout / stride

同样的逻辑 shape，内存可能不同：

```text
contiguous: stride = [N, 1]
transposed: stride = [1, M]
sliced: stride 可能更奇怪
```

layout 决定访问是否连续，直接影响性能。

### 第 4 层：朴素实现

先写最直观的 reference：

```python
ref = torch.softmax(x, dim=-1)
```

或写 Python/C++ 循环。reference 不需要快，但必须清楚、可信。

### 第 5 层：并行映射

问：

```text
一个 thread / warp / block / Triton program 处理什么？
```

常见映射：

- elementwise：一个线程处理一个或多个元素。
- row-wise reduction：一个 block/program 处理一行。
- GEMM：一个 block/program 处理 C 的一个 tile。
- attention：一个 block 处理 Q/K/V 的某些 tile。

### 第 6 层：内存和计算瓶颈

问：

```text
它搬了多少数据？
做了多少计算？
中间结果是否写回 HBM？
```

用 Roofline 粗略判断：

- memory-bound。
- compute-bound。
- launch-bound。
- communication-bound。

### 第 7 层：验证与交付

最后必须有：

- correctness tests。
- benchmark。
- profiling。
- 支持范围。
- 不支持范围。
- README。

## 4. 先学哪些算子

推荐顺序：

```text
elementwise
-> transpose/layout conversion
-> reduction
-> softmax
-> layernorm/rmsnorm
-> GEMM
-> convolution
-> attention
-> quantized GEMM/GEMV
```

这个顺序的好处：

- elementwise 学线程映射。
- transpose 学访存。
- reduction 学同步和归约。
- softmax/norm 把 reduction 用到真实模型。
- GEMM 学高算术强度和 Tensor Core。
- attention 学 IO-aware 重排。
- 量化学 dtype、scale 和 pack。

## 5. 如何判断“我真的学会了”

只看懂文章不算学会。你至少要能做到：

1. 说清数学语义。
2. 写出 reference。
3. 写出最小 kernel 或读懂 kernel。
4. 和 reference 对齐。
5. 跑 benchmark。
6. 解释瓶颈。
7. 说清支持范围。

如果你能把这 7 件事做完，一个算子就入门了。

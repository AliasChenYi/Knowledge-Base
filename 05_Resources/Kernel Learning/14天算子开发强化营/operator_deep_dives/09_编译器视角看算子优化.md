# 09：编译器视角看算子优化

## 1. 为什么算子工程师要懂编译器

即使你主要写手工 kernel，也会遇到：

- TVM。
- MLIR。
- XLA / StableHLO。
- TorchInductor。
- Triton codegen。
- 自研编译器。

编译器的核心问题是：

```text
如何从高层张量表达，自动生成适合硬件的高性能实现。
```

## 2. 算什么 vs 怎么算

Halide 提出的 algorithm/schedule 分离非常重要。

Algorithm：

```text
C[i,j] = sum_k A[i,k] * B[k,j]
```

Schedule：

```text
tile i/j
parallel block
vectorize inner loop
unroll k
cache A/B tile
tensorize MMA
```

手写 CUDA 时你把两者混在一起写；编译器会试图把它们分开。

## 3. 常见优化 Pass

### Graph-level

在计算图层：

- constant folding。
- operator fusion。
- dead code elimination。
- layout propagation。
- common subexpression elimination。

### Operator-level

在 loop/tensor program 层：

- tiling。
- split/fuse loop。
- reorder loop。
- vectorize。
- unroll。
- parallel。
- cache read/write。
- tensorize。

### Codegen-level

在目标代码层：

- instruction selection。
- register allocation。
- memory planning。
- target-specific intrinsic。

## 4. IR 是什么

IR 是 Intermediate Representation，中间表示。

为什么需要 IR：

```text
前端模型很多，后端硬件很多，需要中间层表达和优化。
```

常见 IR：

- PyTorch FX。
- StableHLO/HLO。
- MLIR dialect。
- TVM TensorIR。
- LLVM IR。

## 5. MLIR Dialect

MLIR 用 dialect 表达不同抽象层。

例子：

```text
tensor / linalg / affine / scf / vector / gpu / llvm
```

Lowering：

```text
高层 dialect -> 低层 dialect -> LLVM/目标代码
```

算子工程师不一定每天写 MLIR，但要知道编译器错误可能发生在哪一层。

## 6. TVM TensorIR

TVM TensorIR 把 tensor program 表示成可调度 IR。

Schedule 动作：

- split。
- reorder。
- fuse。
- bind。
- cache_read。
- cache_write。
- vectorize。
- tensorize。

这些动作和你手写 CUDA 的优化非常对应。

## 7. Auto-tuning

很多参数很难手选：

- block size。
- tile M/N/K。
- num warps。
- num stages。
- unroll factor。

Auto-tuning 通过搜索和测量找到更好的组合。

Ansor 的重点是：

- 自动构造搜索空间。
- cost model。
- measurement。

## 8. Fusion 的编译器视角

Fusion 可以减少中间 tensor，但不是总是更快。

编译器要权衡：

- 减少 HBM 读写。
- 减少 launch。
- 增加寄存器压力。
- 增加重复计算。
- 影响并行度。

这解释了为什么 fusion 需要 benchmark。

## 9. Layout 的编译器视角

Layout propagation 很重要。

如果一个 op 喜欢 NHWC，另一个 op 喜欢 NCHW，中间频繁 layout conversion 可能吃掉收益。

编译器会尝试：

- 选择统一 layout。
- 推迟 layout conversion。
- 消除不必要 conversion。
- 为特定后端选择 blocked layout。

## 10. 手写 kernel 和编译器的关系

手写 kernel 适合：

- 极致性能热点。
- 特殊 shape。
- 新硬件 bring-up。
- 编译器还不擅长的 pattern。

编译器适合：

- 大量普通 op。
- 动态图优化。
- 自动融合。
- 跨硬件生成。

成熟工程里两者会共存。

# 入职沟通话术

这份文件不是让你装懂，而是帮你更专业地表达“不懂但我会推进”。

## 1. 不懂需求时

可以说：

```text
我想先确认一下这个算子的语义和验收标准。输入输出 shape、dtype、layout、误差标准和 benchmark shape 列表分别在哪里？
```

## 2. 不懂代码时

可以说：

```text
我正在顺代码路径，想确认一下这个 op 是从哪个 dispatcher/registry 进到这个 backend kernel 的？有没有推荐先看的 example？
```

## 3. 不懂性能瓶颈时

可以说：

```text
我先跑 baseline 和 profiler，看它更像 memory-bound、compute-bound 还是 launch-bound。跑完我整理一份结果再同步。
```

## 4. 需要帮助时

可以说：

```text
我目前卡在 X。已经尝试了 A/B/C，现象是 D。我怀疑是 E，但还不能确认。你方便帮我看一下这个方向是否合理吗？
```

## 5. 汇报风险时

可以说：

```text
当前版本在这些 shape 上 correctness 和性能都通过，但支持范围还有限：只支持 contiguous FP16/FP32，不支持 arbitrary stride 和 backward。我已经在 README 里写清楚了。
```

## 6. 面对“这个为什么慢”

可以说：

```text
我现在还不能直接下结论。我会先估算算术强度，再看 profiler 里的 memory throughput、compute utilization 和 launch timeline，确认瓶颈后再给优化建议。
```

## 7. 面对“你多久能做完”

可以说：

```text
如果只是跑通 baseline 和 correctness，我预计需要 X 天；如果要做 profiling 和给出初步优化方案，需要 Y 天；如果要进主线，还需要补测试和性能回归。
```

## 8. 新人最稳的姿态

```text
我不会假装已经懂所有细节，但我会把语义、测试、benchmark、profiling 和风险逐项确认清楚，并每天给出可验证进展。
```

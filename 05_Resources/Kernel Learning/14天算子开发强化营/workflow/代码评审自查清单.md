# 代码评审自查清单

提交算子相关代码前，先自己过一遍。

## 1. 正确性

- [ ] 和 reference 对齐。
- [ ] 覆盖典型 shape。
- [ ] 覆盖边界 shape。
- [ ] 覆盖 dtype。
- [ ] 覆盖极值。
- [ ] 误差标准写清。
- [ ] 如果不支持 non-contiguous，有明确报错或文档。

## 2. 性能

- [ ] benchmark 命令写清。
- [ ] baseline 明确。
- [ ] 硬件/软件版本记录。
- [ ] warmup 和同步正确。
- [ ] 多 shape 测试。
- [ ] 没有只报最优一次。
- [ ] 性能收益和限制写清。

## 3. 代码质量

- [ ] 命名清楚。
- [ ] 边界条件清楚。
- [ ] 没有魔法数字，或魔法数字有解释。
- [ ] 错误提示清楚。
- [ ] 支持范围写在注释或文档里。
- [ ] 没有无关重构。
- [ ] 没有临时调试输出。

## 4. CUDA/Triton 专项

- [ ] 越界 mask 完整。
- [ ] load/store 都考虑边界。
- [ ] shared memory 读写前后同步正确。
- [ ] reduction 初始化值正确。
- [ ] FP16/BF16 accumulation 合理。
- [ ] BLOCK_SIZE/tile 参数有依据。
- [ ] 没有明显 uncoalesced 访问，或已经解释原因。

## 5. PyTorch/框架接入

- [ ] schema 正确。
- [ ] dtype/device 检查合理。
- [ ] CPU fallback 或 reference 可用。
- [ ] CUDA 错误能及时暴露。
- [ ] tests 能被 CI 或本地命令运行。
- [ ] 文档说明如何调用。

## 6. PR 描述模板

```text
## 背景

## 修改内容

## 正确性

## 性能

## 支持范围

## 风险

## 下一步
```

# 算子开发面试题：入门到进阶

这份题库既能用于面试准备，也能用于每天自测。建议你不要背答案，而是用自己的话讲。

## 1. 硬件与基础

### Q1：GPU 为什么适合深度学习算子？

参考要点：

- 深度学习有大量数据并行。
- GPU 有大量计算单元和高显存带宽。
- 同构、规则计算适合 SIMD/SIMT。
- 但性能依赖访问模式和数据复用。

### Q2：register、shared memory、global memory 的区别是什么？

参考要点：

- register：线程私有，最快，数量有限。
- shared memory：block 内共享，片上高速，需要显式管理。
- global memory：大容量显存，延迟高，带宽高但不是无限。

### Q3：coalescing 是什么？

参考要点：

- 相邻线程访问连续地址。
- 硬件可以合并内存事务。
- 对带宽利用率影响很大。

### Q4：occupancy 越高越好吗？

参考要点：

- 不一定。
- occupancy 高能帮助隐藏延迟。
- 但寄存器、shared memory、指令效率、数据复用也重要。
- 追求的是整体性能，不是单一指标。

## 2. 性能模型

### Q5：Roofline 模型讲的是什么？

参考要点：

- 用算术强度和硬件峰值判断性能上限。
- 区分 memory-bound 和 compute-bound。
- 是方向判断模型，不是精确预测一切。

### Q6：什么是算术强度？

参考：

```text
Arithmetic Intensity = FLOPs / Bytes
```

每搬运 1 byte 数据能做多少计算。

### Q7：vector add 为什么通常 memory-bound？

参考要点：

- 每个元素只做一次加法。
- 需要读两个输入、写一个输出。
- FLOPs/Byte 很低。

### Q8：GEMM 为什么容易有高性能？

参考要点：

- 计算量大。
- A/B 数据可以被多次复用。
- 可以用 tiling 和 Tensor Core/MMA。

## 3. CUDA/Triton 编程

### Q9：CUDA 中全局下标怎么计算？

参考：

```cpp
int idx = blockIdx.x * blockDim.x + threadIdx.x;
```

二维情况下还要分别计算 x/y。

### Q10：为什么 kernel 里常写 `if (idx < n)`？

参考要点：

- grid 通常向上取整。
- 最后一个 block 可能有多余线程。
- 防止越界读写。

### Q11：为什么 GPU 计时要同步？

参考要点：

- kernel launch 异步。
- 不同步会只测到提交开销。
- 用 CUDA event 或 `cudaDeviceSynchronize()`。

### Q12：Triton 的 `program_id` 是什么？

参考要点：

- 当前 program/tile 的编号。
- 用来定位当前 program 处理哪块数据。

### Q13：Triton mask 的作用是什么？

参考要点：

- 防止最后一个 block/tile 越界。
- load/store 都可能需要 mask。

## 4. 常见算子

### Q14：softmax 为什么要减最大值？

参考要点：

- 防止 exp 溢出。
- 分子分母同乘常数，结果不变。
- 最大值变成 0，exp(0)=1。

### Q15：LayerNorm 和 RMSNorm 区别是什么？

参考要点：

- LayerNorm 减 mean，用 variance。
- RMSNorm 不减 mean，用均方根。
- 两者都常用 FP32 accumulate。

### Q16：Reduction 优化有哪些常见点？

参考要点：

- 树形归约。
- 减少分支发散。
- 减少 bank conflict。
- warp-level primitive。
- 每线程处理多个元素。

### Q17：Transpose 为什么是内存优化案例？

参考要点：

- 计算量极少。
- naive 写法一端访问不连续。
- shared memory tile 可以改善 global memory 访问模式。

## 5. GEMM/CUTLASS

### Q18：GEMM 的 CTA tile、warp tile、instruction tile 是什么？

参考要点：

- CTA tile：一个 block 负责的 C 区域。
- warp tile：block 内 warp 分工。
- instruction tile：MMA 指令处理的小矩阵块。

### Q19：epilogue fusion 是什么？

参考要点：

- GEMM 主计算后融合 bias、activation、scale、cast。
- 减少额外 kernel 和 HBM 读写。

### Q20：CUTLASS 和 cuBLAS 区别是什么？

参考要点：

- cuBLAS 是高性能黑盒调用库。
- CUTLASS 是可定制模板库。
- CUTLASS 适合 GEMM 变体和学习/定制。

## 6. Attention/LLM

### Q21：普通 attention 的主要内存问题是什么？

参考要点：

- `QK^T` 产生 `N x N` 中间矩阵。
- softmax 后概率矩阵也是 `N x N`。
- 序列长时 HBM 读写和显存占用大。

### Q22：FlashAttention 为什么快？

参考要点：

- tiling Q/K/V。
- online softmax。
- 避免完整 attention matrix 写回 HBM。
- 是 exact attention，不是近似。

### Q23：FlashAttention-2 相比 1 主要改进什么？

参考要点：

- 更好的并行划分。
- 减少非 matmul 部分开销。
- 提高计算单元利用率。

### Q24：量化算子优化要注意什么？

参考要点：

- scale granularity。
- accumulation dtype。
- 硬件是否支持 INT8/INT4/FP8 指令。
- dequant 是否融合。
- 精度和性能都要评估。

## 7. 工程与测试

### Q25：一个生产可用 custom op 需要哪些部分？

参考要点：

- schema。
- CPU/reference。
- device backend。
- correctness tests。
- benchmark。
- error handling。
- documentation。
- 支持范围说明。

### Q26：你如何设计 correctness test？

参考要点：

- 多 shape。
- 多 dtype。
- 边界 shape。
- non-contiguous。
- 极值。
- 和 reference 比误差。

### Q27：benchmark 要注意什么？

参考要点：

- warmup。
- 同步。
- 多次重复。
- median。
- shape sweep。
- baseline 明确。
- 环境版本记录。

### Q28：优化收益如何汇报？

参考要点：

- 硬件。
- 软件版本。
- shape。
- dtype。
- baseline。
- latency/throughput。
- correctness。
- 适用范围和限制。

## 8. 进阶思考题

### Q29：fusion 一定会变快吗？

参考要点：

- 不一定。
- 可能增加寄存器压力。
- 可能降低 occupancy。
- 可能导致重复计算。
- 需要 benchmark 和 profiling。

### Q30：什么时候不应该手写 kernel？

参考要点：

- vendor library 已经足够快。
- 算子不是热点。
- 维护成本高于收益。
- shape 太多且编译器生成足够好。
- correctness 风险高。

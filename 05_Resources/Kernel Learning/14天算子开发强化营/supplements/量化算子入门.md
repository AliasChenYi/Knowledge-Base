# 量化算子入门

## 1. 量化到底在优化什么

量化的目标通常是：

- 减少显存占用。
- 减少 HBM 带宽压力。
- 使用低精度硬件指令提高吞吐。
- 降低部署成本。

但量化不是白送的。你要付出：

- 精度损失。
- scale/zero point 管理成本。
- dequant/requant 计算开销。
- kernel 复杂度上升。

## 2. 基本公式

对称量化常见形式：

```text
x_float ≈ scale * x_int
```

非对称量化常见形式：

```text
x_float ≈ scale * (x_int - zero_point)
```

反量化：

```text
x_dequant = scale * (x_q - zero_point)
```

## 3. 常见粒度

| 粒度 | 解释 | 优缺点 |
|---|---|---|
| per-tensor | 整个 tensor 一个 scale | 简单，但精度较差 |
| per-channel | 每个输出通道一个 scale | 精度更好，常见 |
| per-group | 每组元素一个 scale | LLM INT4 常见折中 |
| per-token | 每个 token/行一个 scale | 激活动态范围更灵活 |

## 4. Weight-only 量化

LLM 推理中常见：

```text
权重量化成 INT8/INT4，激活保持 FP16/BF16。
```

优点：

- 权重显存和带宽下降。
- 对推理友好。

难点：

- 权重需要 pack。
- matmul/GEMV 时要 dequant。
- dequant 最好融合进主计算。
- scale 读取也会带来额外带宽。

## 5. W8A8

表示：

```text
weight INT8
activation INT8
```

它比 weight-only 更激进，性能潜力更大，但激活量化更难，因为激活动态范围会随输入变化。

SmoothQuant 的核心直觉：

```text
把激活中的 outlier 难题部分迁移到权重上，让 activation 更容易量化。
```

## 6. INT4

INT4 常用于 LLM 权重压缩。

注意：

- 两个 4-bit 值可 pack 到一个 byte。
- unpack 会有开销。
- group size 会影响精度和性能。
- 硬件是否有高效 INT4 指令非常关键。

## 7. FP8

FP8 是低精度浮点，常见于新硬件训练/推理加速。

你要关注：

- FP8 格式，如 E4M3、E5M2。
- scale。
- accumulation dtype。
- 硬件支持。
- 框架/库支持。

## 8. 量化算子的优化点

对于 quantized matmul/GEMM/GEMV，常见优化点：

1. 权重 pack 格式适合连续读取。
2. dequant 和 matmul 融合。
3. scale 缓存在片上或寄存器。
4. accumulation dtype 合理。
5. epilogue 融合 bias/activation/residual。
6. 针对 batch size 和 shape 选择 GEMM 或 GEMV 策略。

## 9. 玩具实验建议

先做 INT8 weight-only GEMV：

```text
输入:
  x: FP16 [K]
  w_q: INT8 [N, K]
  scale: FP16/FP32 [N]
输出:
  y: FP16 [N]

计算:
  y[n] = sum_k x[k] * (w_q[n,k] * scale[n])
```

最低要求：

- Python reference。
- C++/CUDA/Triton 玩具实现。
- 测 max error。
- 测不同 N/K。

## 10. 常见坑

- 只看压缩率，不看 dequant 开销。
- scale 粒度选得太细，scale 读取反而贵。
- pack 格式不适合内存合并。
- INT4 unpack 吃掉收益。
- 量化后单算子误差小，但端到端模型质量下降。
- 没确认目标芯片是否有对应低精度指令。

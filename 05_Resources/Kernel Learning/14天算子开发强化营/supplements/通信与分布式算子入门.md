# 通信与分布式算子入门

## 1. 为什么算子工程师也要懂通信

单卡算子优化很重要，但大模型训练和推理经常是多卡/多芯片系统。很多时候端到端性能不是某个 matmul 慢，而是：

- allreduce 等通信慢。
- KV cache 或参数跨设备搬运。
- 计算和通信没有 overlap。
- pipeline/tensor parallel 切分不合理。

你不需要一开始成为分布式专家，但要能听懂基本词。

## 2. 常见通信原语

| 原语 | 作用 |
|---|---|
| broadcast | 一个设备发给多个设备 |
| reduce | 多个设备的数据合并到一个设备 |
| allreduce | 所有设备都得到 reduce 后结果 |
| allgather | 每个设备收集所有设备的数据 |
| reduce-scatter | reduce 后按块分发给各设备 |
| all-to-all | 每个设备和每个设备交换不同数据 |

## 3. 训练里常见通信

数据并行：

```text
每张卡有完整模型，不同 batch。
反向传播后梯度需要 allreduce。
```

张量并行：

```text
一个大矩阵或大层切到多张卡。
中间结果常需要 allreduce/allgather/reduce-scatter。
```

流水并行：

```text
模型层切到不同卡。
activation 在 stage 之间传递。
```

## 4. 推理里常见通信

LLM 推理中：

- tensor parallel 的 matmul 后可能 allreduce。
- expert parallel/MoE 可能 all-to-all。
- KV cache 可能跨设备管理。
- 多机 serving 还涉及调度和网络。

## 5. 通信和算子怎么 overlap

优化目标：

```text
计算时让通信也在后台进行，减少等待。
```

常见手段：

- 分块计算。
- 异步通信。
- stream 分离。
- reduce-scatter 替代 allreduce 某些路径。
- fusion 小通信。

## 6. 你作为新人要会问什么

1. 这个性能问题是单卡 kernel 慢，还是通信等待？
2. timeline 里计算和通信是否重叠？
3. 通信量是多少？
4. 用的是 NCCL、RCCL、HCCL，还是厂商自研通信库？
5. 张量并行切分方式是什么？
6. 这个 op 的输出是否马上参与通信？

## 7. 最小学习实验

如果有多卡环境，尝试：

1. 用 PyTorch distributed 跑 allreduce。
2. 测不同 tensor size 的 latency/bandwidth。
3. 用 profiler 看通信 timeline。
4. 尝试计算和 allreduce overlap。

如果没有多卡环境：

- 先理解原语语义。
- 看 Nsight Systems timeline 示例。
- 看 LLM tensor parallel 的 matmul + allreduce 数据流。

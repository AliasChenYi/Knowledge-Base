# 多后端与芯片平台迁移地图

## 1. 为什么要补这个

你即将入职的是芯片公司，不一定只用 NVIDIA CUDA。你现在学 CUDA/Triton 不是为了把自己绑定在 NVIDIA 上，而是为了学习一套可迁移的思想：

```text
线程层级、片上存储、访存合并、分块、归约、融合、性能模型
```

这些思想会在 HIP、SYCL、Ascend C、BANG C、自研 DSL 中以不同名字出现。

## 2. 概念迁移表

| 通用概念 | NVIDIA CUDA | AMD HIP/ROCm | Intel/SYCL | 昇腾/寒武纪等 NPU |
|---|---|---|---|---|
| 设备 kernel | CUDA kernel | HIP kernel | SYCL kernel | 自定义算子 kernel |
| 线程块 | block/CTA | block/workgroup | work-group | block/task 类似概念 |
| 线程 | thread | work-item | work-item | 计算单元内并行 lane |
| warp 类执行组 | warp | wavefront | sub-group | 向量/矩阵执行组 |
| global memory | global/HBM | global/HBM | global memory | 外部显存/HBM |
| shared memory | shared memory | LDS | local memory | 片上 SRAM/UB |
| 同步 | `__syncthreads()` | `__syncthreads()` | barrier | 平台同步原语 |
| profiling | Nsight | rocprof | VTune | 厂商 profiler |

不同平台细节不一样，但你先抓共性。

## 3. 到新平台先问什么

入职后如果目标是自研芯片或国产 NPU，先问：

1. 最小执行单元是什么？
2. 并行层级怎么组织？
3. 片上存储有哪些？容量多大？
4. 数据从 HBM 到片上怎么搬？是否有 DMA？
5. 是否有矩阵乘专用指令？
6. 支持哪些 dtype？
7. 是否支持异步 copy 或 pipeline？
8. profiler 能看到哪些指标？
9. 官方高性能库有哪些？
10. custom op 如何接入框架？

## 4. CUDA 思想如何迁移

### Coalescing

在 CUDA 里叫 coalesced access。其他平台可能不这么叫，但本质都是：

```text
让相邻执行 lane 访问连续地址，提高内存事务效率。
```

### Shared Memory / SRAM

名字可能不同：

- CUDA shared memory。
- AMD LDS。
- NPU unified buffer / local memory。

本质：

```text
片上高速小容量存储，用来缓存 tile 和提高复用。
```

### Tiling

所有平台都重要：

```text
把大矩阵/大张量切成能放进片上存储的小块。
```

### Fusion

所有平台都重要：

```text
减少中间 tensor、减少外存读写、减少调度开销。
```

## 5. 迁移时最容易踩的坑

1. 以为 CUDA block size 可以直接照搬。
2. 以为 shared memory 容量和 bank 结构一样。
3. 以为同样 dtype 都有同样吞吐。
4. 以为 profiler 指标一一对应。
5. 忽略厂商库已有更优实现。
6. 没看目标平台的 memory alignment 要求。
7. 没确认 atomic、同步、异步 copy 语义差异。

## 6. 新平台学习路径

第一天：

- 跑官方 vector add。
- 跑官方 matmul 或 conv 示例。
- 找到 profiler。

第一周：

- 写 elementwise。
- 写 reduction。
- 写 softmax 或 norm。
- 读官方 custom op 接入文档。

第一个月：

- 跑通一个真实模型里的小算子。
- 做 benchmark。
- 做 profiler。
- 和 vendor library 或旧实现对比。

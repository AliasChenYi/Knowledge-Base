# 入职 30-60-90 天行动计划

这份计划帮你把入职后的前三个月拆成可执行目标。目标不是装作专家，而是稳稳建立可信度。

## 前 30 天：跑通环境，做小闭环

### 核心目标

```text
能独立跑测试、跑 benchmark、看懂一个小算子的代码和结果。
```

### 你要完成

- [ ] 搭好开发环境。
- [ ] 跑通团队官方 demo。
- [ ] 跑通至少一个 benchmark。
- [ ] 找到 correctness reference。
- [ ] 找到 profiler 使用方法。
- [ ] 读懂一个简单算子。
- [ ] 修一个小 bug 或补一个测试。

### 不要急着做

- 不要一上来重写核心 attention。
- 不要没有 baseline 就宣布优化。
- 不要不懂装懂硬件细节。

### 你应该多问

```text
这个算子的验收 shape 列表在哪里？
误差标准是什么？
baseline 是谁？
历史上有没有 profiling 结果？
```

## 第 31-60 天：承担一个小性能任务

### 核心目标

```text
能对一个真实小算子做 baseline、profiling、优化和报告。
```

### 你要完成

- [ ] 选择一个明确的小算子任务。
- [ ] 写清输入输出和支持范围。
- [ ] 跑 baseline。
- [ ] 跑 profiler。
- [ ] 做 1-2 个小优化。
- [ ] 补 correctness tests。
- [ ] 写性能报告。

### 合适任务

- elementwise fusion。
- layernorm/rmsnorm 小优化。
- softmax 某些 shape 优化。
- transpose/layout conversion 优化。
- 补 benchmark harness。

### 汇报模板

```text
我针对 X 算子，在 shape A/B/C 上做了测试。
baseline 是 Y。
profiling 显示主要瓶颈是 Z。
我做了优化 W，收益在 shape A 上是 P%，在 shape B 上不明显。
目前限制是 R，下一步计划是 S。
```

## 第 61-90 天：形成独立判断

### 核心目标

```text
能判断一个任务该手写、调库、用 Triton，还是交给编译器。
```

### 你要完成

- [ ] 熟悉团队代码结构。
- [ ] 熟悉目标硬件关键限制。
- [ ] 能读懂 profiler 指标。
- [ ] 能独立设计测试覆盖。
- [ ] 能评估优化收益和维护成本。
- [ ] 能写清楚技术方案。

### 判断问题

拿到任务先问：

1. 这是热点吗？
2. baseline 有多强？
3. shape 是否固定？
4. dtype 是否固定？
5. 需要支持动态 shape 吗？
6. 是否已有 vendor library？
7. 手写 kernel 的维护成本是否值得？
8. correctness 风险在哪里？

## 90 天后的能力画像

比较理想的状态：

```text
你不一定能写出最强 kernel，但你能把一个算子任务拆清楚：
语义、数值、性能、工程接入、测试、风险和下一步。
```

这已经是很扎实的工程起点。

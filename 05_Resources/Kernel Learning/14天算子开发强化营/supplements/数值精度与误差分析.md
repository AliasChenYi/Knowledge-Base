# 数值精度与误差分析

## 1. 为什么算子会“看起来对，但又不完全一样”

浮点数不是实数。不同实现的计算顺序、累加精度、向量化方式、并行归约顺序都可能导致结果有微小差异。

所以算子正确性不是简单地问：

```text
是否逐 bit 完全一致？
```

而是问：

```text
在指定 dtype 和语义下，误差是否在可接受范围内？
```

## 2. 常见 dtype

| dtype | 特点 | 常见用途 |
|---|---|---|
| FP32 | 精度较高，速度/显存成本较高 | reference、累加 |
| TF32 | NVIDIA Tensor Core 常见格式，范围类似 FP32、尾数更少 | Ampere 以后 FP32 matmul 加速 |
| FP16 | 显存小、吞吐高、范围小 | 训练/推理 |
| BF16 | 指数范围接近 FP32，尾数少 | 训练/推理 |
| FP8 | 更低精度，依赖硬件和 scale | 新硬件 LLM |
| INT8 | 整数量化 | 推理 |
| INT4 | 更强压缩 | LLM weight-only |

## 3. 为什么 reduction 容易有误差

浮点加法不满足严格结合律：

```text
(a + b) + c 不一定逐 bit 等于 a + (b + c)
```

并行 reduction 会改变求和顺序，所以结果和 PyTorch/CPU reference 可能略有差异。

常见策略：

- FP16/BF16 输入，FP32 累加。
- 设置合理 `rtol/atol`。
- 对误差做 max/mean/p99 分析。
- 对关键 op 做端到端精度验证。

## 4. allclose 怎么看

PyTorch 的 `allclose` 大致判断：

```text
abs(a - b) <= atol + rtol * abs(b)
```

其中：

- `atol`：绝对误差容忍。
- `rtol`：相对误差容忍。

建议学习期参考：

| dtype | rtol | atol |
|---|---:|---:|
| FP32 | 1e-5 | 1e-6 |
| FP16 | 1e-2 | 1e-3 |
| BF16 | 2e-2 | 2e-2 |
| INT8/INT4 | 视量化方案和任务而定 | 视量化方案和任务而定 |

真实项目必须以团队标准为准。

## 5. Softmax 的数值稳定

错误写法：

```text
exp(x) / sum(exp(x))
```

如果 `x` 很大，`exp(x)` 会溢出。

稳定写法：

```text
m = max(x)
exp(x - m) / sum(exp(x - m))
```

这是等价变换，但能显著降低溢出风险。

## 6. LayerNorm/RMSNorm 的数值注意点

LayerNorm：

```text
mean = sum(x) / N
var = sum((x - mean)^2) / N
y = (x - mean) / sqrt(var + eps)
```

RMSNorm：

```text
rms = sqrt(mean(x^2) + eps)
y = x / rms
```

注意：

- 统计量建议 FP32。
- eps 加在 sqrt 或 rsqrt 前。
- PyTorch LayerNorm 默认使用 biased variance，语义要对齐。
- weight/bias 的 dtype 和输出 cast 顺序会影响误差。

## 7. NaN/Inf 排查流程

1. 输入是否已有 NaN/Inf？
2. 是否出现除 0？
3. 是否 exp 溢出？
4. 是否 sqrt 负数？
5. 是否未初始化内存？
6. mask 的填充值是否合理？
7. dtype 是否范围太小？

建议临时加检查：

```python
print(torch.isnan(x).any(), torch.isinf(x).any())
print(x.min(), x.max())
```

## 8. 什么时候要追求 bitwise 一致

大多数高性能算子不要求和 reference 逐 bit 一致，但以下场景可能要求更严格：

- deterministic training。
- 单元测试要求固定输出。
- 金融/科学计算等高精度场景。
- 特定后端一致性测试。

如果要 deterministic，性能可能下降，因为你限制了并行归约顺序和原子操作行为。

```text
reference:
dtype:
shape:
rtol:

max_abs_error:
max_rel_error:

```

这会让你的报告非常专业。

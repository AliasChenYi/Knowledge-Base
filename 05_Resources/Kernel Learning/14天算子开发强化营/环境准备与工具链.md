# 环境准备与工具链

这份文件不是让你一次性装完所有东西，而是帮你知道算子开发常见环境由哪些部分组成。入职后公司通常有内部环境，你要做的是知道每个工具解决什么问题。

## 1. 最小学习环境

如果你走 CUDA/NVIDIA 路线，最小环境通常包括：

```text
NVIDIA GPU
NVIDIA Driver
CUDA Toolkit
Python
PyTorch
Triton
Nsight Compute / Nsight Systems
CMake / Ninja
Git
```

如果你走 AMD 路线：

```text
AMD GPU
ROCm
HIP
PyTorch ROCm build
rocprof / rocprofiler
```

如果你走国产 NPU/芯片公司路线：

```text
厂商 SDK
厂商编译器
厂商 runtime
厂商 profiler
框架适配层
自定义算子工具链
```

概念大多相通：kernel language、runtime、profiler、library、framework integration。

## 2. 版本信息记录模板

每次 benchmark 都要记录环境：

```text
OS:
GPU/NPU:
Driver:
CUDA/ROCm/CANN/CNToolkit:
Python:
PyTorch:
Triton:
Compiler:
Commit:
Date:
```

为什么重要：

- 不同驱动和库版本性能可能不同。
- 同事复现需要环境信息。
- 以后性能回归要能追溯。

## 3. 常用命令

### NVIDIA

```powershell
nvidia-smi
nvcc --version
```

Linux 下常见：

```bash
nvidia-smi
nvcc --version
nsys --version
ncu --version
```

### Python/PyTorch

```python
import torch
print(torch.__version__)
print(torch.version.cuda)
print(torch.cuda.get_device_name(0))
print(torch.cuda.get_device_capability(0))
```

### Triton

```python
import triton
print(triton.__version__)
```

## 4. 计时工具分层

| 场景 | 工具 |
|---|---|
| 单个 CUDA kernel | CUDA event |
| PyTorch/Triton 函数 | `triton.testing.do_bench` 或 `torch.utils.benchmark` |
| 端到端 timeline | Nsight Systems |
| 单 kernel 指标 | Nsight Compute |
| CPU hotspot | perf / VTune |

## 5. Debug 建议

CUDA 调试时可以临时用：

```text
CUDA_LAUNCH_BLOCKING=1
```

作用：

```text
让 CUDA 操作同步执行，错误更容易定位。
```

注意：

```text
这会影响性能，不能用于正式 benchmark。
```

## 6. 入职后环境摸底清单

第一天问清楚：

1. 公司推荐开发机/容器是什么？
2. SDK 版本怎么切换？
3. benchmark 必须在哪台机器跑？
4. profiler 是否需要权限？
5. 是否有内部性能数据库？
6. correctness reference 在哪里？
7. 测试数据和 shape 列表在哪里？
8. 提交代码是否有 CI？

# 算子验收清单

以后你每写一个算子，都可以按这份清单验收。

## 1. 语义

- [ ] 输入 shape 明确。
- [ ] 输出 shape 明确。
- [ ] dtype 支持范围明确。
- [ ] layout 支持范围明确。
- [ ] 是否支持 non-contiguous 明确。
- [ ] 是否支持 broadcast 明确。
- [ ] 边界条件明确。
- [ ] 和框架 reference 语义一致。

## 2. 数值

- [ ] FP32/FP16/BF16/INT8 等误差标准明确。
- [ ] reduction 是否用 FP32 accumulate 明确。
- [ ] NaN/Inf 行为明确。
- [ ] eps 位置明确。
- [ ] 量化 scale/zero point 规则明确。
- [ ] 随机测试通过。
- [ ] 极值测试通过。

## 3. 性能

- [ ] baseline 明确。
- [ ] benchmark shape 来源明确。
- [ ] warmup 已做。
- [ ] 同步计时正确。
- [ ] median/p50 或多次重复已记录。
- [ ] 硬件和软件版本已记录。
- [ ] 小 shape 和大 shape 都测过。
- [ ] 性能收益适用范围写清。

## 4. Profiling

- [ ] 初步判断 memory-bound / compute-bound。
- [ ] 有 profiler 证据。
- [ ] global memory throughput 已看。
- [ ] occupancy 或资源使用已看。
- [ ] register spill 已检查。
- [ ] shared memory bank conflict 风险已考虑。
- [ ] launch overhead 已考虑。

## 5. 工程集成

- [ ] Python/C++ API 明确。
- [ ] CPU fallback 或 reference 明确。
- [ ] CUDA/Triton/后端实现注册正确。
- [ ] 错误提示清楚。
- [ ] 不支持场景会报错或 fallback。
- [ ] tests 已接入。
- [ ] benchmark 已接入。

## 6. 文档

- [ ] README 写清用法。
- [ ] 支持范围写清。
- [ ] 不支持范围写清。
- [ ] benchmark 命令写清。
- [ ] 关键设计解释写清。
- [ ] 下一步优化写清。

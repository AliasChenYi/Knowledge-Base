生成日期：2026-05-26  
适用对象：即将入职芯片/AI 加速器/深度学习框架团队，岗位方向是算子开发、算子适配、性能优化、推理训练加速。

> 先把心放稳一点：算子开发不是“入职第一天就手搓 Tensor Core 汇编”。真实工作更像是把数学语义、硬件特性、框架接口、测试基准和性能剖析拧到一起。你现在什么都不懂并不可怕，可怕的是乱学。下面这份路线的目标是让你从“完全陌生”走到“能看懂任务、能跑基准、能定位瓶颈、能做出可验证优化”。

## 1. 算子开发到底是什么

深度学习模型看起来是 Transformer、CNN、推荐模型、扩散模型，但落到硬件上，最终会变成一个个张量操作：

- `matmul / gemm`
- `conv`
- `softmax`
- `layernorm / rmsnorm`
- `attention`
- `embedding / gather / scatter`
- `topk / sort`
- `quantize / dequantize`
- `allreduce / reduce_scatter`

**算子开发**就是为这些操作写出正确、快、稳定、可集成的实现。

一个合格算子通常要同时回答五个问题：

1. **语义是否正确**：shape、dtype、broadcast、stride、layout、边界条件、NaN/Inf 行为是否和框架一致。
2. **数值是否可靠**：FP32/FP16/BF16/FP8/INT8/INT4 下误差是否可控，是否需要 FP32 accumulation。
3. **性能瓶颈在哪里**：是访存带宽、计算吞吐、寄存器压力、同步、launch overhead、还是数据布局转换。
4. **怎么接入生态**：PyTorch/TensorFlow/ONNX/编译器 IR/运行时/自研框架如何注册、调度、fallback。
5. **怎么证明有效**：单测、随机测试、梯度测试、benchmark、profiling、回归基准是否完整。

所以算子工程师不是只会写 CUDA/Ascend C/BANG C 的人，而是能把“数学公式 -> 张量布局 -> 并行程序 -> 性能证据 -> 框架集成”完整闭环的人。

## 2. 学习主线总览

你要抓住三条主线。

### 2.1 数学与张量语义

核心问题：这个算子究竟算什么？

你需要掌握：

- 线性代数：矩阵乘、向量点积、范数、转置、广播。
- 深度学习常见层：Linear、Conv、Attention、Normalization、Activation。
- 张量元信息：shape、stride、layout、contiguous、dtype、alignment。
- 数值稳定性：softmax 减最大值、LayerNorm 方差、混合精度累加、量化 scale/zero point。

### 2.2 硬件与性能模型

核心问题：为什么这个实现慢？

你需要掌握：

- CPU：cache、SIMD、prefetch、NUMA、线程池、向量化。
- GPU/NPU：线程/warp/wave、block/CTA、SM/CU/AI Core、寄存器、shared memory/SRAM、L2、HBM。
- 性能模型：Roofline、算术强度、memory-bound、compute-bound。
- 优化套路：tiling、fusion、vectorized load/store、coalescing、bank conflict、occupancy、pipeline。

### 2.3 软件栈与工程闭环

核心问题：写好的 kernel 怎么进入真实模型？

你需要掌握：

- 框架层：PyTorch custom op、dispatcher、autograd、`torch.compile`/Inductor。
- Kernel 语言：CUDA C++、HIP、Triton、Ascend C、BANG C、SYCL/DPC++。
- 专用库：cuBLAS/cuDNN、CUTLASS、oneDNN、rocBLAS/MIOpen、CNNL、CANN。
- 编译器：TVM TensorIR、MLIR、StableHLO、XLA、auto-tuning。
- 工具：Nsight Compute/Systems、rocprof、VTune、perf、benchmark harness。

## 3. 入职前 14 天救急路线

目标不是变专家，而是让你能听懂需求、跑通样例、知道怎么查资料、敢于问对问题。

### Day 1-2：建立硬件直觉

读：

- NVIDIA CUDA C++ Programming Guide 的 introduction、programming model、memory hierarchy。
- CUDA Best Practices Guide 的 memory coalescing、shared memory、occupancy。
- Roofline 论文或 LBNL Roofline 页面。

做：

- 画一张图：CPU 内存层次 vs GPU 内存层次。
- 写下这 6 个词的解释：HBM、shared memory、register、warp、occupancy、coalescing。

验收：

- 你能解释“为什么 GPU 算得很快但经常卡在访存”。

### Day 3-4：写第一个 kernel

做：

- CUDA 或 Triton 写 `vector_add`。
- 写 `transpose`，比较 naive transpose 和 tiled transpose。
- 用 CUDA event 或 Triton benchmark 计时。

验收：

- 能说出“连续访问”和“非连续访问”为什么性能差很多。

### Day 5-6：Reduction、Softmax、LayerNorm

做：

- 写 row-wise sum/max。
- 写稳定 softmax：先减每行最大值，再 exp，再 sum，再除。
- 写 LayerNorm/RMSNorm forward。

验收：

- 和 PyTorch 输出比误差。
- 对不同 shape 做 benchmark。

### Day 7：接入 PyTorch custom op

读：

- PyTorch 官方 Custom C++ and CUDA Operators 教程。

做：

- 把一个简单 CUDA kernel 注册成 PyTorch op。
- 用 `torch.library.opcheck` 或随机测试验证。

验收：

- Python 里能调用你的自定义 op。

### Day 8-10：Triton 快速上手

读：

- Triton 官方 fused softmax、matrix multiplication、layer norm 教程。

做：

- 用 Triton 重写 softmax。
- 用 Triton 写 matmul 教程版本。
- 比较 PyTorch eager、`torch.compile`、Triton 自定义 kernel。

验收：

- 能解释 `program_id`、block size、mask、power-of-two padding。

### Day 11-12：GEMM 与 CUTLASS

读：

- NVIDIA Deep Learning Performance 的 Matrix Multiplication Background。
- CUTLASS Efficient GEMM in CUDA。

做：

- 手写一个 tiled GEMM，哪怕不快。
- 看懂 GEMM 的 CTA tile、warp tile、MMA/tensor core、epilogue。

验收：

- 能解释为什么 GEMM 是“算子优化的中心战场”。

### Day 13：Attention 与 FlashAttention

读：

- FlashAttention NeurIPS 2022 论文摘要和算法图。
- FlashAttention-2 的 work partitioning 思路。

做：

- 写一页笔记：普通 attention 的中间矩阵为什么浪费 HBM。

验收：

- 能解释 IO-aware attention 的核心思想：少把中间结果写回慢内存。

### Day 14：整理自己的入职包

产出一个小仓库或笔记：

- `vector_add`
- `transpose`
- `softmax`
- `layernorm`
- `matmul`
- 每个算子的 correctness test
- 每个算子的 benchmark 表
- 每个算子的 profiling 截图或日志

这就是你入职时的“我已经能开始干活”的证据。

## 4. 6 个月成长路线

### 阶段 1：基础工程能力，2-3 周

你要能舒服地写 C++/Python/Linux 工程。

学习内容：

- C++：指针、引用、模板基础、RAII、`std::vector`、`span`/指针视图、编译链接。
- Python：NumPy/PyTorch 张量操作、pytest、benchmark 脚本。
- Linux：shell、`cmake`、`make`、环境变量、动态库、`ldd`、`nm`。
- Git：分支、diff、commit、rebase 基础。

推荐资料：

- PyTorch Custom C++ and CUDA Operators：官方讲 custom op 的推荐路径。
- PyTorch Performance Tuning Guide：先理解框架层已有优化。

练习：

- 写一个 C++ CPU op：`y = relu(a * x + b)`。
- Python 里用 pybind11 或 PyTorch extension 调它。
- 和 PyTorch reference 对齐。

阶段验收：

- 能读懂编译报错。
- 能写随机测试。
- 能做最小 benchmark。

### 阶段 2：GPU/NPU 并行编程入门，1-2 个月

学习内容：

- 线程组织：grid/block/thread，warp/wavefront。
- 内存：global/HBM、shared/SRAM、register、constant、L2。
- 常见问题：访存合并、bank conflict、分支发散、occupancy、寄存器溢出。
- 同步：block 内同步、原子操作、stream、event。

推荐资料：

- CUDA Programming Guide。
- CUDA Best Practices Guide。
- NVIDIA Efficient Matrix Transpose 博客。
- AMD ROCm/HIP Programming Guide，用来建立跨厂商映射。

练习：

- vector add
- tiled transpose
- reduction
- prefix sum 简化版
- softmax
- layernorm/rmsnorm

阶段验收：

- 给一个慢 kernel，你能先猜是访存问题还是计算问题，再用 profiler 验证。

### 阶段 3：GEMM、卷积与张量核心，2-3 个月

学习内容：

- GEMM：`C = alpha * A * B + beta * C`
- tiling：block tile、warp tile、thread tile。
- Tensor Core/MMA：为什么矩阵乘不是普通 FMA 堆出来的。
- Epilogue fusion：bias、activation、scale、residual add。
- Conv lowering：im2col、implicit GEMM、Winograd 直觉。

推荐资料：

- NVIDIA Matrix Multiplication Background User's Guide。
- CUTLASS Efficient GEMM in CUDA。
- CUTLASS 3.x GEMM API。
- CuTe GEMM tutorial。

练习：

- 手写 naive GEMM。
- 手写 shared-memory tiled GEMM。
- 使用 CUTLASS 跑一个 GEMM 示例。
- 做 shape sweep：M/N/K 从小到大，画性能曲线。

阶段验收：

- 能解释为什么小 batch GEMV、常规 GEMM、batched GEMM、grouped GEMM 的优化策略不同。

### 阶段 4：框架集成与测试体系，3-4 个月

学习内容：

- PyTorch dispatcher、Dispatch Key、custom op schema。
- CPU/CUDA/ROCm 多后端注册。
- autograd：forward/backward kernel。
- FakeTensor/meta kernel：让编译器知道 shape。
- `torch.compile` 和 custom op 兼容。

推荐资料：

- PyTorch Custom C++ and CUDA Operators。
- PyTorch Operator Registration。
- PyTorch Dispatcher tutorial。

练习：

- 实现一个 PyTorch custom op：`rms_norm(x, weight, eps)`。
- 支持 CPU reference 和 CUDA/Triton 加速版本。
- 写 randomized tests、dtype tests、non-contiguous tests。

阶段验收：

- 你的 op 能被模型调用，不只是单独跑 kernel。

### 阶段 5：编译器、IR 与自动调优，4-5 个月

学习内容：

- 计算图层：operator fusion、layout propagation、constant folding。
- 算子层：loop nest、schedule、tiling、vectorize、unroll、tensorize。
- IR：TVM TensorIR、MLIR dialect、StableHLO/HLO。
- auto-tuning：搜索空间、cost model、measurement、database。

推荐资料：

- TVM OSDI 2018 论文。
- TVM TensorIR 官方文档。
- Ansor OSDI 2020 论文。
- MLIR Toy tutorial。
- MLIR paper。
- OpenXLA StableHLO spec 和 XLA:GPU architecture overview。

练习：

- 用 TVM TensorIR 写 matmul schedule。
- 尝试 MetaSchedule 或 DLight。
- 看一段 StableHLO/HLO IR，找 fusion。

阶段验收：

- 能解释“手写 kernel”和“编译器生成 kernel”各自适合什么场景。

### 阶段 6：LLM 推理/训练热点算子，5-6 个月及以后

学习内容：

- Attention：MHA/MQA/GQA、causal mask、KV cache。
- FlashAttention：online softmax、tiling、IO-aware。
- PagedAttention：KV cache 分页管理。
- 量化：FP8、INT8、INT4、weight-only、activation-aware、SmoothQuant、AWQ。
- 通信：allreduce、reduce-scatter、all-gather 与算子/通信 overlap。

推荐资料：

- FlashAttention、FlashAttention-2、FlashAttention-3。
- vLLM/PagedAttention 论文。
- TensorRT-LLM 文档。
- SmoothQuant、AWQ、LLM.int8 论文。

练习：

- 实现一个 forward-only mini FlashAttention。
- 实现 INT8 weight-only GEMV/GEMM 玩具版。
- 对比普通 attention 和 fused attention 的内存占用。

阶段验收：

- 能从模型结构里识别真正的性能热点，而不是盲目优化冷门小算子。

## 6. 必做练习项目

每个项目都要有三件产物：正确性测试、benchmark、profiling 或瓶颈分析。

### 项目 1：Elementwise + Broadcast

任务：

- 实现 `y = gelu(x * scale + bias)`。
- 支持 contiguous 和简单 broadcast。

重点：

- grid-stride loop
- vectorized load/store
- dtype 处理

成功标准：

- 与 PyTorch 对齐。
- 性能至少比纯 Python 快，不一定比 PyTorch 内置快。

### 项目 2：Reduction

任务：

- 实现 row-wise sum/max。
- 支持 `M x N`，N 从 32 到 8192。

重点：

- block 内归约
- warp-level reduce
- shared memory 与寄存器

成功标准：

- 能解释不同 N 下为什么性能变化。

### 项目 3：Softmax

任务：

- 实现稳定 softmax。
- 先写 CUDA/Triton forward。

重点：

- 减最大值
- 两次 reduction
- 避免中间结果写回 HBM

成功标准：

- 误差可控。
- profile 显示主要瓶颈在哪里。

### 项目 4：LayerNorm/RMSNorm

任务：

- 实现 forward。
- 可选实现 backward。

重点：

- mean/variance reduction
- FP32 accumulation
- vectorized memory access

成功标准：

- 和 PyTorch reference 对齐。
- 处理多种 hidden size。

### 项目 5：Tiled GEMM

任务：

- naive GEMM -> shared-memory tiled GEMM -> 调用 CUTLASS。

重点：

- tile 分块
- 数据复用
- arithmetic intensity
- epilogue

成功标准：

- 能画出 M/N/K sweep 的性能曲线。

### 项目 6：PyTorch Custom Op

任务：

- 把 RMSNorm 或 Softmax 接入 PyTorch。

重点：

- op schema
- CPU fallback
- CUDA/Triton backend
- tests

成功标准：

- 模型代码能调用。
- 有随机测试和边界测试。

### 项目 7：Mini FlashAttention

任务：

- 实现 forward-only causal attention 玩具版。

重点：

- online softmax
- tiling Q/K/V
- 减少 HBM 读写

成功标准：

- 能解释普通 attention 和 FlashAttention 的内存流量差异。

### 项目 8：量化 GEMV/GEMM 玩具版

任务：

- 实现 INT8 weight-only GEMV。
- 支持 per-channel scale。

重点：

- pack/unpack
- scale/dequant
- accumulation dtype

成功标准：

- 能说明准确率误差来自哪里，性能收益来自哪里。

## 7. 工作中真正会用到的检查清单

### 7.1 正确性清单

写 kernel 前先列清楚：

- 输入 shape、输出 shape。
- dtype：FP32、FP16、BF16、INT8、FP8 是否支持。
- layout：NCHW、NHWC、row-major、column-major、blocked layout。
- stride：是否只支持 contiguous，还是支持 arbitrary stride。
- broadcast：哪些维度允许广播。
- 边界：空 tensor、非 2 的幂、奇数长度、小 shape、大 shape。
- 数值：NaN/Inf、溢出、下溢、rounding、accumulation。
- deterministic：是否要求确定性结果。

测试至少覆盖：

- 随机 shape。
- 极小 shape：1、2、3。
- 非对齐 shape：31、63、127、1000。
- 大 shape。
- non-contiguous tensor。
- 不同 dtype。
- 和 reference 比误差。

### 7.2 Benchmark 清单

不要只跑一次然后宣布“快了 3 倍”。

要做：

- warmup。
- `cudaDeviceSynchronize()` 或正确使用 event。
- 固定输入、固定 seed。
- 跑多次，报告 median/p50/p90/p99。
- sweep shape，不只测一个 shape。
- 和合理 baseline 比：PyTorch、cuBLAS/cuDNN、Triton、旧实现。
- 记录硬件、驱动、CUDA/ROCm/CANN 版本。

### 7.3 Profiling 清单

看到慢，先问：

- 是 kernel launch overhead 吗？小 tensor 特别容易中招。
- 是 HBM 带宽打满了吗？
- 是 Tensor Core 没用上吗？
- 是 occupancy 太低吗？
- 是寄存器太多导致 spill 吗？
- 是 shared memory bank conflict 吗？
- 是 uncoalesced load/store 吗？
- 是 layout conversion 或 memcpy 吃掉时间了吗？
- 是多个小 kernel 没融合导致中间 tensor 太多吗？

### 7.4 优化动作清单

常见动作按优先级：

1. 确认算法复杂度没有错。
2. 减少 HBM 读写。
3. 改 layout 或让访问连续。
4. fusion，减少中间 tensor 和 launch。
5. tiling，提高数据复用。
6. vectorized load/store，提高内存事务效率。
7. 调 block size，平衡 occupancy 和寄存器。
8. shared memory 避免 bank conflict。
9. 使用 tensor core/MMA。
10. auto-tuning 搜索参数。
11. 高阶：async copy、pipeline、TMA、warp specialization、persistent kernel。

## 8. 常见术语速查

| 术语 | 直觉解释 |
|---|---|
| Operator / Op / 算子 | 张量层面的操作，比如 matmul、softmax |
| Kernel | 设备上实际执行的一段并行程序 |
| Launch overhead | CPU 提交 kernel 到设备执行的开销 |
| HBM / Global memory | 大容量但相对慢的设备显存 |
| Shared memory / SRAM | 片上小容量高速存储，需要程序员显式管理 |
| Register | 每个线程私有最快存储，但数量有限 |
| Warp / Wavefront | GPU/NPU 上一起调度执行的一组线程 |
| Occupancy | 一个 SM/CU 上活跃 warp/block 的程度 |
| Coalescing | 相邻线程访问连续地址，合并成更少内存事务 |
| Bank conflict | shared memory 多线程访问冲突，导致串行化 |
| Tiling | 把大问题切成小块，提高片上数据复用 |
| Fusion | 多个操作合成一个 kernel，减少中间结果和访存 |
| Arithmetic intensity | 每搬运一个 byte 能做多少计算 |
| Memory-bound | 主要瓶颈在数据搬运 |
| Compute-bound | 主要瓶颈在计算单元吞吐 |
| Epilogue | GEMM 主计算后的融合操作，如 bias、relu、scale |
| Layout | 张量在内存中的排列方式 |
| Stride | 每个维度移动一步对应的内存偏移 |
| Autotuning | 自动搜索 block size、tile size 等实现参数 |
| Dispatch Key | PyTorch 用来选择 CPU/CUDA/自定义后端实现的机制 |
| HLO / StableHLO | ML 编译器中描述高层张量操作的 IR |

## 9. 入职后 90 天怎么活得漂亮

### 第 1 周：先摸清战场

你要主动搞清楚：

- 目标芯片是什么。
- 编程模型是什么：CUDA/HIP/Ascend C/BANG C/SYCL/自研 DSL。
- 主要服务训练还是推理。
- 热点模型是什么：CNN、Transformer、推荐、LLM、多模态。
- 性能指标是什么：latency、throughput、tokens/s、TFLOPS、带宽、功耗。
- benchmark 怎么跑。
- correctness reference 是什么。
- profiler 用哪个。

建议你这样问：

> 这个算子的 reference 实现和验收误差标准在哪里？benchmark shape 列表是否有线上代表性？现在瓶颈是访存、计算还是调度开销，有没有历史 profiling 结果？

这句话会让别人觉得你是来解决问题的，不是来背 API 的。

### 第 1 个月：接一个小算子闭环

目标：

- 跑通环境。
- 改一个小 bug。
- 优化一个简单 op。
- 补一组测试。

不要一上来挑战最复杂的 attention kernel。先把工程链路摸通。

### 第 2 个月：拥有一个性能任务

目标：

- 对一个真实 hot op 做 baseline。
- 给出 profiling 证据。
- 做 1-2 个小优化。
- 写清楚收益和适用 shape。

重点不是“绝对性能逆天”，而是“证据链完整”。

### 第 3 个月：开始形成判断力

你要能判断：

- 这个 op 值不值得手写。
- 调库、Triton、CUTLASS、编译器生成哪个更合适。
- 当前瓶颈是算法、kernel、layout、框架调度还是通信。
- 优化是否会破坏数值稳定性或维护性。

## 11. 论文怎么读，不要被公式吓住

读系统/算子论文，按四遍法。

第一遍，10 分钟：

- 看标题、摘要、图 1、结论。
- 只回答：它解决什么瓶颈？

第二遍，30 分钟：

- 看方法部分的大图和伪代码。
- 只回答：它减少了什么开销？计算、访存、通信、显存，还是调度？

第三遍，1-2 小时：

- 看关键公式和实验设置。
- 只回答：它在哪些 shape、硬件、模型上有效？

第四遍，动手复现：

- 找官方代码或最小实现。
- 跑一个小 case。
- 写 benchmark。

读 FlashAttention 时就这样读：

- 瓶颈：普通 attention 会产生巨大中间矩阵，HBM 读写太多。
- 方法：tiling + online softmax。
- 条件：适合长序列 attention。
- 复现：先写 forward-only 小版本。

## 12. 不要踩的坑

1. **只看 FLOPS，不看数据搬运**：很多算子不是算不动，是搬不动。
2. **只测一个 shape**：算子性能高度 shape-dependent。
3. **不做 synchronize 就计时**：GPU 异步执行会让时间完全不可信。
4. **把个人博客当事实**：博客可以帮理解，但关键结论要回到官方文档和论文。
5. **上来就啃 CUTLASS 模板**：先写朴素 GEMM，再看 CUTLASS。
6. **忽略数值稳定性**：softmax、norm、量化最容易“看起来快，结果错”。
7. **只写 kernel，不接框架**：工程价值来自端到端可用。
8. **盲目融合**：fusion 可能增加寄存器压力，反而变慢。
9. **过度追求通用**：生产里常为关键 shape 写专门优化。
10. **害怕问问题**：新人不知道硬件细节很正常，但要带着 benchmark 和 profiling 结果问。

## 14. 最后给你一段“入职心法”

你不需要假装自己懂。你需要做到三件事：

1. **每个结论有证据**：代码、测试、benchmark、profiling。
2. **每个问题能拆开**：语义问题、数值问题、性能问题、集成问题分开看。
3. **每天推进一个小闭环**：今天跑通，明天测准，后天优化一点。

算子开发像修一条高速路：数学语义是地图，硬件是地形，kernel 是路面，profiler 是测速仪，测试是护栏。你现在不是没有路，你只是刚拿到地图。照着这份路线走，入职后至少不会慌，而且会越来越能看见问题的骨架。

# CLIProxyAPI 服务搭建与 Codex 客户端配置

## Scope
记录在云服务器上部署 API 代理服务，并让 Windows 端 Codex Desktop / CLI 使用该服务的配置流程。

## Sensitive Info Policy
- 不在知识库中保存真实 API key、订阅链接、私钥、账号密码或付款链接。
- 真实值只放在本机密码管理器、服务器环境变量或私有配置文件中。
- 如果真实 token 曾经写入笔记、提交区或远端仓库，应尽快在上游平台轮换。

## Environment
| Item | Value |
| --- | --- |
| Server | `<SERVER_IP>` |
| API port | `<PROXY_PORT>` |
| API base URL | `http://<SERVER_IP>:<PROXY_PORT>/v1` |
| Model provider | `cliproxyapi` |
| Token source | `<PRIVATE_VAULT_OR_ENV>` |

## 1. 安装 Codex CLI
在 Linux 服务器上安装 Codex CLI：

```bash
curl -fL -o codex.tar.gz https://github.com/openai/codex/releases/latest/download/codex-x86_64-unknown-linux-musl.tar.gz
tar -xzf codex.tar.gz
sudo install -m 0755 codex-x86_64-unknown-linux-musl /usr/local/bin/codex
codex --version
```

## 2. 开放服务端口
确认本机服务监听端口：

```bash
ss -ltnp | grep ":<PROXY_PORT>"
```

如果服务器启用了本机防火墙，需要放行端口：

```bash
sudo ufw allow <PROXY_PORT>/tcp
sudo ufw status
```

云厂商控制台也需要配置安全组入站规则：

```text
Protocol: TCP
Port: <PROXY_PORT>
Source: <TRUSTED_CLIENT_IP_OR_CIDR>
```

## 3. Windows Codex 配置
在 Windows 端打开 Codex 配置文件：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex"
notepad "$env:USERPROFILE\.codex\config.toml"
```

示例配置如下，真实 token 不写入知识库：

```toml
model = "<MODEL_NAME>"
model_provider = "cliproxyapi"
model_reasoning_effort = "xhigh"
plan_mode_reasoning_effort = "xhigh"
supports_websockets = true

[model_providers.cliproxyapi]
name = "cliproxyapi"
base_url = "http://<SERVER_IP>:<PROXY_PORT>/v1"
wire_api = "responses"
requires_openai_auth = true
experimental_bearer_token = "<API_KEY_FROM_PRIVATE_VAULT>"
```

## 4. 验证连通性
从 Windows PowerShell 检查 API 是否可访问：

```powershell
curl.exe "http://<SERVER_IP>:<PROXY_PORT>/v1/models" `
  -H "Authorization: Bearer <API_KEY_FROM_PRIVATE_VAULT>"
```

从服务器本机检查代理服务：

```bash
curl -s "http://127.0.0.1:<PROXY_PORT>/v1/models" \
  -H "Authorization: Bearer <API_KEY_FROM_PRIVATE_VAULT>"
```

## Troubleshooting
- `Connection refused`：服务没有启动、监听地址只绑定了 `127.0.0.1`，或端口未开放。
- `Timed out`：云安全组、防火墙或客户端网络阻断。
- `401 / 403`：token 错误、过期，或代理服务鉴权配置不一致。
- `model not found`：`model` 字段与代理服务暴露的模型名不一致。
- Codex Desktop 未生效：重启 Codex Desktop，并确认读取的是 `%USERPROFILE%\.codex\config.toml`。

## Maintenance Checklist
- 记录服务部署路径、启动方式和日志路径。
- 端口、域名、模型名变化后同步更新本文件的占位符说明。
- token 定期轮换，轮换日期记录在私有密码管理器中。
- 真实配置文件不提交到 Git；只提交脱敏示例。
